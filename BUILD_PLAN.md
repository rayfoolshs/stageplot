# StagePlot — Build Plan

A web app to build **stage plots and technical riders** for live music, inspired by
Ridermaker. This document is the plan of record before any code is written.

- **Target scope:** MVP + accounts / cloud save
- **Frontend:** React + TypeScript (Vite)
- **Status:** M0–M6 complete — MVP plus accounts, cloud save, sharing, and a
  live static build on GitHub Pages

---

## 1. Goals

Deliver a usable product where a musician or sound tech can:

1. Drag instruments, mics, monitors and other stage items onto a stage plot.
2. Position, resize, rotate, flip and layer those items.
3. Build a **channel list** (inputs) and a simple **output list**.
4. Add footer / contact / production notes.
5. Export the whole thing as a **PDF** (portrait or landscape).
6. **Register / log in**, save riders to the cloud, reopen and edit them.
7. **Share** a rider via a public read-only link.

## 2. Non-goals (explicitly deferred)

These are real Ridermaker features we are **not** building in this phase. Listed so
we do not accidentally half-build them.

- Subscriptions, trials, billing, invoices (no Stripe yet).
- **Mixer export** (X32, X Air, CL/QL, RIVAGE, WING, dLive, Avantis, Ui12/16).
  Each is a distinct file-format research project.
- "Tech Hub" public directory of riders.
- Multi-language (EN/ES). English only for now; i18n-ready structure, but no ES.
- The suggestions/roadmap/help-center subsystem.
- Custom-column colors per cell, output list parity, item legend — can land later.

## 3. Legal / IP note

We build our **own** implementation. The interaction patterns (drag-drop stage plot,
channel list) are fair to emulate. We must **not** copy Ridermaker's item artwork,
icons, marketing copy, or code. Our stage-item library will be our own SVGs or
openly-licensed icons.

## 4. Architecture overview

```
┌──────────────────────────────┐        ┌───────────────────────────────┐
│  Web client (React + TS)     │  HTTP  │  API (Node + Fastify + TS)    │
│                              │ ─────▶ │                               │
│  /            editor         │        │  /api/auth/*                  │
│  /login /register            │        │  /api/riders/*                │
│  /riders      my riders      │        │  /api/assets/*                │
│  /s/:token    public share   │        │  /api/render/pdf (Puppeteer)  │
│  /print/:id   print view     │        │                               │
└──────────────────────────────┘        └───────────────┬───────────────┘
                                                         │
                                                 ┌───────▼────────┐
                                                 │  PostgreSQL    │
                                                 │  + file store  │
                                                 └────────────────┘
```

**Single source of truth:** a rider is a pure **JSON document** (`StageDoc`).
The editor renders it with React. The PDF is generated by rendering the *same*
React print components in a headless browser (Puppeteer) — so the PDF always
matches what the user sees. No second layout engine to keep in sync.

### Why these choices

| Concern        | Choice                          | Reason |
|----------------|---------------------------------|--------|
| Editor surface | DOM/SVG with absolute transform | Easiest to manipulate, hit-test and select items |
| Exact PDF      | Puppeteer on a `/print` route   | Pixel parity with the editor, one layout source |
| Auth           | Email + password, httpOnly cookie sessions | Simple, no third-party dependency to start |
| DB access      | Prisma                          | Typed schema, easy migrations |
| Database       | SQLite now, PostgreSQL at M4    | Zero-setup local dev; swap via one Prisma provider line |
| File storage   | Local disk in dev, S3-compatible later | Uploaded custom images |
| Styling        | Tailwind CSS                    | Fast iteration on the editor UI |

## 5. Tech stack

**Client**
- Vite + React 18 + TypeScript
- State: Zustand (editor document + selection + history)
- Routing: React Router
- Canvas/UX: plain DOM + CSS transforms; `@use-gesture/react` optionally for drag/resize
- Forms/validation: react-hook-form + zod
- Styling: CSS Modules (or Tailwind — decide at scaffold time)

**Server**
- Node + Fastify + TypeScript
- Prisma ORM + PostgreSQL
- Sessions: signed httpOnly cookie (`@fastify/cookie` + `@fastify/session`)
- Password hashing: argon2
- Uploads: `@fastify/multipart`
- PDF: Puppeteer (headless Chromium) rendering the client `/print` route
- Validation: zod (shared schemas with client)

**Tooling**
- npm workspaces (monorepo): `apps/web`, `apps/api`, `packages/shared`
  (npm instead of pnpm: pnpm isn't installed and `npm.ps1` is blocked by this
  machine's PowerShell execution policy — `npm.cmd` works, so npm workspaces it is)
- ESLint + Prettier, Vitest (unit), Playwright (e2e happy path)

## 7. The core document: `StageDoc`

The whole editor is a function of this object. Keep it stable and versioned.

```ts
type StageDoc = {
  version: 1;
  stage: {
    width: number;          // world units
    height: number;
    background?: string;    // asset id or preset key
  };
  items: StageItem[];       // z-order = array order (last = on top)
  texts: TextItem[];
  arrows: ArrowItem[];
  channels: ChannelRow[];   // input list
  outputs: ChannelRow[];
  footer: { text: string };
  meta: { name: string; orientation: 'portrait' | 'landscape' };
};

type StageItem = {
  id: string;
  itemKey: string;          // which library item
  x: number; y: number;
  w: number; h: number;
  rotation: number;         // degrees
  flipX: boolean; flipY: boolean;
  label?: string;           // custom caption
};

type ChannelRow = {
  id: string;
  number: number;
  source: string;
  mic?: string;
  stand?: string;
  phantom?: string;
  notes?: string;
  [custom: string]: string | number | undefined;
};
```

Rendering (`items` in order) + the channel list table + footer => both the editor
view and the print view. The print view is just the read-only render at print DPI.

## 8. Editor feature spec (MVP)

**Library**
- Categorized item library: Drums, Guitars, Amps, Keys, Strings, Winds, Mics,
  Audio, People, Text, Stages/Lighting. Our own SVGs.
- Search + favorites (star an item). Free-tier favorites limit (e.g. 5) — we won't
  enforce paid gating yet, but keep the field.

**Canvas**
- Drag from library to canvas (HTML5 DnD or pointer events).
- Select (click), multi-select (shift / marquee), move (drag), delete.
- Handles: resize corner, rotate handle, flip buttons.
- Layer: bring forward / send back / to front / to back.
- Magnetic grid toggle; snap to grid.
- Zoom / pan.
- Undo/redo (command stack in Zustand).
- Keyboard: arrow nudge, Delete, Ctrl+Z / Ctrl+Shift+Z, Ctrl+D duplicate.

**Channel list**
- Add/remove rows, auto-numbering.
- Columns: #, source, mic, stand, phantom, notes (fixed set for MVP).
- Editable table.
- Output list (monitors / in-ears) — simple version.

**Footer / meta**
- Name, free-text footer (character limit).
- Orientation portrait/landscape.

**Export**
- Button → POST doc to `/api/render/pdf` → returns PDF blob → download.
- Print view route renders identical layout.

## 9. PDF generation

Approach: **client print route + server Puppeteer**.

1. Client has `/print/:id` (and a draft print via in-memory doc) rendering the
   read-only layout at fixed page size (A4/Letter, chosen orientation).
2. API `/api/render/pdf` receives the doc (or rider id), launches Puppeteer,
   navigates to the print route (auth via short-lived signed token), waits for
   `document.fonts.ready` and images, then `page.pdf({ format, landscape })`.
3. Streams the PDF back.

Fallbacks considered: `@react-pdf/renderer` (no browser, but a second layout to
maintain) and `svg-to-pdf` (great for the stage but awkward for the table). The
Puppeteer route wins on fidelity and single-source layout.

Perf note: run Chromium as a warm singleton pool; cap concurrency.

## 10. API surface

```
POST   /api/auth/register      { email, password }        -> sets session cookie
POST   /api/auth/login         { email, password }
POST   /api/auth/logout
GET    /api/auth/me

GET    /api/riders                                        -> list (own)
POST   /api/riders             { name, doc }              -> create
GET    /api/riders/:id
PUT    /api/riders/:id         { name, doc }              -> autosave target
DELETE /api/riders/:id

POST   /api/riders/:id/share   -> returns shareToken
DELETE /api/riders/:id/share
GET    /api/share/:token                                  -> public read-only doc

GET    /api/favorites
PUT    /api/favorites          { itemKey }                -> toggle

POST   /api/assets             multipart image            -> { id, url }
POST   /api/render/pdf         { doc } | { riderId }      -> application/pdf
```

Autosave: debounce PUT `/api/riders/:id` ~1.5s after edits.

## 11. Security & privacy

- Sessions: httpOnly, sameSite=lax, secure in prod. CSRF token for mutating routes.
- Password: argon2id, min length enforced; rate-limit login.
- Ownership checks on every `/api/riders/:id` and `/api/assets/*`.
- Share links: unguessable token; `isPublic` toggle; revoke deletes token.
- Uploads: validate mime + size (e.g. ≤5 MB), store outside web root, serve via
  signed URL or controlled route.
- Do not log rider contents or emails in plaintext beyond what's needed.

- [x] Portrait/landscape, one-click download from the toolbar

### M3 — Accounts ✅ (done)
- [x] Register/login/logout, session cookie, `/api/auth/me`
- [x] Login + register screens, guest-route redirect
- [x] Argon2id hashing, per-IP rate limits, origin check + SameSite=Lax CSRF defence

Implementation notes:
- Session cookie `stageplot.sid` (`httpOnly`, `SameSite=Lax`, `secure` in prod,
  30 days) in `@fastify/session`'s in-memory store (dev). The session is
  **regenerated on login/register** so a pre-login cookie can't be fixated.
- Passwords are **argon2id** (`@node-rs/argon2`, 19 MiB / t=2 / p=1). Unknown
  emails still burn an argon2 verify so timing doesn't leak accounts.
- Limits: 10/min per IP on login, 5 per 10 min on register.
- CSRF: `SameSite=Lax` plus an Origin allow-list (`WEB_ORIGIN`) on every
  state-changing auth route; requests without an Origin (curl) are allowed.
- The editor stays usable without an account (local-first). The only guard for
  now is the guest redirect on `/login` and `/register`; rider-ownership guards
  arrive with M4.
- Prisma: `npm run db:push` creates `apps/api/prisma/dev.db` from
  `apps/api/.env` (`DATABASE_URL`).

### M4 — Cloud save & My Riders ✅ (done)
- [x] Rider CRUD API + ownership
- [x] Autosave, thumbnails
- [x] "My riders" list: open, rename, duplicate, delete
- [ ] Custom image uploads (`/api/assets`) — **deferred**: needs a custom-item
      model on `StageDoc` (itemKey + asset reference), not just a file endpoint

Implementation notes:
- Routes: `GET/POST /api/riders`, `GET/PUT/DELETE /api/riders/:id`. Every query
  is scoped by `userId`; someone else's id returns **404**, not 403, so ids
  aren't probeable. Documents are validated with the shared `StageDoc` schema.
- `PUT` accepts a full `doc` (name derives from `doc.meta.name`) or just a
  `name` for list renames, which rewrites `doc.meta.name` server-side so the
  list and the printed title never drift.
- Autosave: 1 s debounce, requests serialised (a save in flight queues one
  more), status shown in the toolbar (`Saving… / Saved / Save failed`).
- Thumbnails are SVG data URLs rendered client-side from the **same**
  `StageSvg` used by the print view, capped at 200 KB server-side.
- The editor is still local-first: `/` edits the localStorage draft, and a
  signed-in user can promote it with **Save to cloud** (binds the doc to a new
  rider and swaps the URL to `/r/:id` without a reload).
- New routes: `/riders` (list) and `/r/:id` (editor bound to a rider). Both
  redirect to `/login?next=…` when signed out; `next` is same-origin-only.
- Body limit raised to 3 MB for docs with thumbnails.

### M5 — Sharing ✅ (done)
- [x] Share token create/revoke
- [x] `/s/:token` public read-only view + "print" from share
- [x] Favorites API

Implementation notes:
- Tokens are 24 random bytes (base64url). Re-sharing an active link returns the
  same token; after a revoke, sharing mints a **new** token so an old link can
  never be revived. Revoking nulls the token *and* `isPublic`.
- `GET /api/share/:token` is unauthenticated but returns only
  `{ name, thumbnail, updatedAt, doc }` — never the owner or other riders. It
  sends `Cache-Control: no-store` so revocation is immediate, and is rate
  limited to 60/min per IP.
- `/api/riders` summaries now include `shareToken`/`isPublic` (owner-scoped) so
  the list can show a **Shared** badge and the editor knows the link state.
- The public page reuses `PrintSheet`, so the shared view, the print dialog and
  the PDF are byte-for-byte the same layout. It offers **Download PDF** (the
  render endpoint is public) and **Print**.
- Favorites: `GET /api/favorites`, and `PUT /api/favorites { itemKey }` toggles.
  The library shows a star on each tile (signed-in only) and a **★ Favorites**
  filter chip; toggles are optimistic and reverted if the request fails.

### M6 — Polish ✅ (done)
- [x] Magnetic grid + marquee multi-select
- [x] Empty/loading/error states, toasts
- [x] Playwright happy-path e2e
- [x] Basic responsive layout (editor is desktop-first)
- [ ] Canvas pan gesture (wheel/scrollbars work today; a space-drag pan is a
      nice follow-up)

Implementation notes:
- **Marquee**: drag on empty stage selects intersecting items, shapes and texts
  (text bounds are estimated from font size); Shift adds to the selection.
- **Magnetic grid**: moving items snaps to the 25-unit grid whenever the grid is
  visible; hold **Alt** for free placement. Resizing stays free-form.
- **Toasts**: small bottom-right stack (`ui/toast.ts` + `Toaster`), auto-dismiss
  after 4.5 s. Used for autosave failure (once per failure streak), cloud-save
  success/error, share-link copy, favorites errors and PDF fallback.
- **Empty stage** shows a drag-from-library hint.
- **Responsive**: the editor has a 1100px minimum and scrolls horizontally below
  that (desktop-first); riders/auth/share pages reflow on their own.
- **E2E**: `npm run test:e2e` runs `e2e/happy-path.spec.ts` in Playwright using
  the installed Chrome (`channel: "chrome"`), starting the dev servers when
  needed. The happy path registers, drags a monitor onto the plot, saves to the
  cloud, verifies autosave, finds the rider in My riders and reopens it.

## 14. Risks & open questions

- **Puppeteer in production** (memory, cold start). Mitigation: warm pool, queue,
  concurrency cap; or move to a hosted browser service later.
- **Stage item artwork.** We need our own SVG set; sourcing it is real effort.
  Start with ~20–30 and grow.
- **PDF fidelity** of fonts across OS. Mitigation: bundle webfonts, await
  `document.fonts.ready` before printing.
- **Autosave conflicts** if the same rider is open in two tabs. Mitigation: last
  write wins for MVP; add `updatedAt` check later.
- **Open:** A4 vs Letter default; storage host for prod; Tailwind vs CSS Modules.

## 15. Delivered beyond the original plan

These landed after M1 (all in `apps/web`):

### 15.1 Item library expansion
46 items across 12 categories (added **Lighting** and **Video**, the latter with
LED TV panels and a video wall). Clean, top-down artwork with a shared stroke
language; icons tint to the selection color.

### 15.2 Item labels
Items carry a caption (defaults to the library name) rendered under the item on
the canvas. Toggle all labels from the toolbar; edit per item in the inspector.

### 15.3 Drawing tools (shapes)
- Tools: **Select / Rect / Circle (ellipse) / Polygon**.
- Rect & ellipse: drag out a box; polygon: click vertices, then **Enter**,
  **double-click**, or click near the first point to close; **Esc** cancels.
- Editing: select, move, resize (corner), rotate; **polygon vertex handles**;
  filled / outline toggle; optional label; delete.
- Model: `ShapeItem` on `StageDoc.shapes`. Polygon vertices are stored
  **normalized inside the bounding box**, so resizing the box scales the shape.
- Rendering: one SVG per shape in stage units, violet accent to distinguish
  shapes from equipment.

### 15.4 Light / dark theme
Toolbar toggle (☾/☀), light by default, persisted to `localStorage`. Implemented by remapping
Tailwind's `neutral` palette variables under `html.light`, so the entire UI
remaps with no per-component rewrites.

### 15.5 Mixing-desk input list
An editable input list is pinned below the stage (and prints with the rider):
columns **Channel · Instrument · Person · Input type · Microphone · Monitor FB ·
DCA/Subgroup · Notes**, with add/remove rows and auto-numbering. "Input type" is a
dropdown (Mic / DI / Line / Wireless). Backed by `StageDoc.channels`; `person`,
`monitor`, `dca` and `inputType` were added to `ChannelRow`.

### 15.6 Fixes
- Delete / Backspace removes the selected item / text / shape.
- Canvas gestures blur a focused inspector field so shortcuts act on the canvas.
- Fixed a Strict Mode double-invoke bug: a side effect inside a `setState`
  updater created **two** polygons per Enter press.
- Autosave skipped the first edit after opening a document (the skip flag was
  set before the subscription existed). Autosave now ignores the loaded document
  object itself, so the first real edit persists — local drafts and cloud riders.

### 15.7 PDF export (M2)
- **One layout source.** `apps/web/src/print/PrintSheet.tsx` renders the rider
  (stage SVG, input list, monitors, footer) at exact A4 size. The on-screen
  print view, the browser's print dialog and the server-side PDF all use it.
- **`/print`** is a standalone route (path switch in `main.tsx`, no router). It
  reads the doc from `localStorage` (`stageplot:print-doc`, falling back to the
  autosaved draft). The API seeds that key in headless Chrome before the page
  boots, so the renderer never needs a network round-trip for the document.
- **`POST /api/render/pdf`** validates the body with the shared zod schema,
  then prints `/print` with `puppeteer-core` + the system Chrome
  (`CHROME_PATH`, else the usual macOS/Linux/Windows locations). One warm
  browser, one render at a time, closed on SIGINT/SIGTERM.
- **Fidelity:** waits for `document.fonts.ready` (page sets
  `data-print-ready`), `printBackground: true`, `preferCSSPageSize: true`.
- **Fallback:** if the API is unreachable (or no Chrome), the toolbar opens
  `/print` in a tab, where "Print / Save as PDF" uses the browser engine.

### Known dev caveat
Editing the store module while the dev server runs can leave the global keyboard
listener bound to a stale store instance. Hard-refresh (Ctrl+Shift+R) after
pulling changes.

## 17. Deployment (GitHub Pages)

The web app is published as a **static demo** at
<https://rayfoolshs.github.io/stageplot/>.

- `npm run build:pages` builds `apps/web` with base `/stageplot/`, writes
  `404.html` (SPA fallback for deep links such as `/print`) and sets
  `VITE_STATIC_DEMO=1`.
- `src/lib/appPath.ts` prefixes internal links/redirects with Vite's base so the
  same code works at `/` locally and under the Pages subpath.
- The static build hides the account UI (there is no API) and the Export button
  becomes **Print / Save PDF**, which opens the print view synchronously so the
  popup isn't blocked.
- `.github/workflows/deploy-pages.yml` builds and deploys on every push to
  `main`; Pages is configured with **Source: GitHub Actions**.
- The API is **not** deployed: accounts, cloud save, sharing, favorites and the
  server PDF renderer require running `apps/api` (or hosting it separately).

## 18. How to run

```bash
npm install
cp apps/api/.env.example apps/api/.env   # then edit SESSION_SECRET
npm run db:push
npm run dev:api     # http://127.0.0.1:3001
npm run dev:web     # http://localhost:5173  (proxies /api -> api)

npm run build       # typecheck + production build
npm run build:pages # static demo for GitHub Pages (base /stageplot/)
npm run test:e2e    # Playwright happy path
```

On Windows, use `npm.cmd` (see the README).
